# Codex desktop routing design

The user has authorized a matched comparison of Luna-low and Sol-low followed by installation of the winning judge. Correctness and override handling outrank latency. A tie on correctness is broken by median single-prompt latency. Both candidates receive the same frozen stricter policy and examples three times; results and selection are published alongside the initial report.

The desktop integration is a local executable adapter selected through the app's existing `CODEX_CLI_PATH` override. It starts the original bundled Codex executable unchanged, relays JSONL traffic, and adjusts only new `turn/start` model/effort settings. It also updates collaboration-mode settings, which otherwise take precedence. All other requests and permissions pass through unchanged. Unsupported transports and ordinary CLI commands delegate directly to the real binary.

A separate, isolated native Codex app-server uses the existing ChatGPT login to judge prompts. It disables plugins, hooks, notifications and delegation, uses ephemeral threads, and has a bounded timeout. Its auth file is an alias to native auth, never a duplicated key or token. The adapter does not store prompt text in its status log. It maintains only bounded in-memory recent context for the judge.

Initial worker policy is conservative: automatic work stays on GPT-6.1 Sol, using low, medium or extra-high effort. A suggested Luna worker maps to Sol-low; an Astra suggestion maps to Sol-extra-high. Explicitly selected other models and maximum/Ultra effort are preserved. Automatic model switching remains off until more representative worker evaluations establish benefits. This installs the original feature's automatic effort selection without trusting the failed unrestricted downgrades.

An explicit model/effort change through `thread/settings/update`, or a changed per-turn selection, disables Auto for that chat. Bare acknowledgements preserve the active effort. Auto can be resumed through the controller. Invalid judge JSON, an unavailable model, a timeout, attached inputs and disabled Auto forward the original request. A cancelled pending turn is acknowledged as cancelled and never submitted to the main worker. Interrupts and approvals are never queued behind a judge. New turns on the same thread preserve order; separate threads may proceed independently.

The controller supports status, Auto on/off and changing the judge. Installation places versioned source under the user's local data library, a launcher on the user PATH, and an explicit-only controller skill in the normal global library. The existing Codex/Devin skill sync is run and checked. A login service preserves the desktop executable override after login. Uninstall restores the prior override and removes only this installation's managed files.

Verification includes contract tests, a real proxy-to-Codex request showing the effective effort, preservation of manual selection, a forced timeout, large JSONL frames, cancellation, a matched judge comparison, and installation checks. Desktop activation requires the app to start a new backend; ongoing chats are not terminated to accomplish that. The installer configures future desktop launches, and reports any remaining restart clearly.
